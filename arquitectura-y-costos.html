Demo · Terraform

VPN site-to-site AWS ↔ Google Cloud

Arquitectura que implementa el Terraform y estimado de costos de tenerlo encendido 3 días (72 horas)

Arquitectura

AWS hace de “nube” (DynamoDB + Lambda) y Google Cloud simula el on-premise con SQL Server en Docker. Se unen con una VPN IPsec de 2 túneles y BGP.

Cómo se conectan

Una sola conexión VPN de AWS trae 2 túneles que apuntan a una customer gateway, que es la interfaz 0 del HA VPN de GCP. Ambos túneles aprenden las rutas por BGP, sin rutas estáticas. Es un demo sin alta disponibilidad: el SLA de 99.99% pide 4 túneles.

Cómo llega la Lambda a AWS sin NAT

La VPC no tiene Internet Gateway ni NAT. La Lambda usa un endpoint Gateway para DynamoDB (gratis) y un endpoint Interface para Secrets Manager (1 AZ, cobra por hora). Lo único que sale de la VPC es el tráfico a 10.10.1.0/24 por la VPN.

Se activa con una variable

El flujo ② (Streams, event source mapping y DLQ SQS) solo existe con enable_streams_sync = true. Por defecto es false, así que el full load corre primero. El estimado de costos asume que está activado.

Qué simula “on-premise”

La VM de GCP representa el SQL Server on-premise. Su firewall solo deja pasar tcp 1433 desde las dos subnets privadas de AWS. El Terraform puede dejarla con IP externa efímera (por defecto) solo para descargar la imagen.

Supuestos

  • Mínimo: solo los cargos fijos por hora y por almacenamiento. Probable: suma las IPs externas de GCP y un poco de tráfico y servicios por uso.
  • Regiones: las que define variables.tf por defecto, us-east-1 en AWS y us-east4 en GCP.
  • VM: e2-medium (2 vCPU, 4 GB) con disco pd-balanced de 30 GB, tal como lo declara el Terraform. Imagen COS sin licencia de SO de pago.
  • Tráfico: bajo, para unos 100 a 200 registros. Un full load y algunos eventos de Streams mueven bien menos de 1 GB.
  • Streams activado (enable_streams_sync = true): agrega la DLQ SQS y el event source mapping, que no tienen costo apreciable aquí.
  • Mes de 720 horas para prorratear el secreto. Cada hora parcial se cobra como hora completa en los recursos por hora.
  • Free tier y créditos: no se descuentan. AWS y Google pueden tener capa gratuita o créditos que bajarían el total real, sobre todo Lambda, DynamoDB, CloudWatch y SQS.
  • Impuestos y soporte no incluidos.

Lo que más pesa es lo que cobra por hora aunque no se use

La VPN de AWS, los 2 túneles de HA VPN en GCP, el endpoint Interface y la VM suman cerca del 90% del total. No dependen de cuántos datos muevas. Encendido todo, el demo gasta unos US$ 0.22 por hora (unos US$ 5 por día). Si se olvida prendido un mes completo serían unos US$ 157.

Cómo bajarlo: corre terraform destroy apenas termines, o enciende todo solo el día de la charla (unas horas cuestan centavos, no dólares) y ensaya antes con una corrida corta.

Al terminar: destruir todo

Un solo comando borra la VPN, la VM, la Lambda y las tablas en ambas nubes.

terraform destroy

Recordatorio de apagado

Después de destruir, revisa en la consola de AWS (VPN, VPC, Lambda, DynamoDB) y en la de GCP (Compute Engine, VPN, Cloud Router) que no quede nada. Un recurso olvidado sigue cobrando por hora.
